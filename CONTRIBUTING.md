# Contributing to Raziel

Start with the [quickstart](docs/quickstart.md) and pick the component that owns the change. Use this repo for the project overview, component pins, diagrams, and showcase site. Send runtime and SDK changes to the respective component repositories.

- **Backend:** describe the policy or authorisation case, expected outcome, and a reproduction using synthetic inputs.
- **SDK:** include the package version, request type, and a minimal example that omits tokens and private keys.
- **Demo agents:** name the affected console and task step. Use synthetic records and remove credentials from screenshots.
- **Showcase:** open `site/index.html` to preview it. Preserve separate paths to official voting and to the design-partner form.

For a pull request, describe what changed and how you checked it. Read the component's contributor instructions before modifying a pinned checkout. Report vulnerabilities privately through the affected repository's security reporting channel if available. Keep tokens, private relationship evidence, and sensitive records out of public issues.

## Research direction

Raziel's proof-backed grants are the starting point. Hypha explores how agents can find relevant data, check authority, and bound disclosure across teams. Open questions include permission freshness across organisations and the cumulative privacy cost of repeated queries.
